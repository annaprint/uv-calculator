# Памятка: очистка каталога товаров и переимпорт

**Когда нужна эта инструкция:**
Импортировали через админку **не тот** `catalog.xlsx` → нужно вычистить старые товары и загрузить правильный файл.

---

## Кратко: что делает импорт

«📦 Каталог товаров» → «Загрузить catalog.xlsx» делает **upsert по артикулу**:
- Артикулы, которые есть в новой xlsx → перезаписываются (название, цвета и т.д. обновятся).
- Артикулы, которые **были** в БД, но **нет** в новой xlsx → **остаются** как мусор.

Если новая xlsx покрывает весь правильный ассортимент — можно просто загрузить её сверху, не очищая. Но если хотите гарантированно чистый каталог — делайте полную очистку (ниже).

---

## Полная очистка → загрузка правильной xlsx

### 1. Подключиться к VDS

В Терминале на маке (`Cmd+Space` → «Терминал»):

```
ssh root@217.149.30.8
```

Введите root-пароль (символы не отображаются). Должно появиться приглашение `root@7632525-dd737634:~#`.

### 2. Очистить таблицу `catalog_items`

```
sudo -u uvcalc sqlite3 /opt/uv-calc/data/uv.db "DELETE FROM catalog_items;"
```

Никакого вывода — это норма.

### 3. Проверить что пусто

```
sudo -u uvcalc sqlite3 /opt/uv-calc/data/uv.db "SELECT COUNT(*) FROM catalog_items;"
```

Должно вывести `0`.

### 4. Закрыть SSH

```
exit
```

### 5. В админке загрузить правильную xlsx

1. Открыть https://calc.citi-print.ru/admin.html
2. Войти под админом
3. «📦 Каталог товаров»
4. **«📂 Загрузить catalog.xlsx»** → выбрать **правильный** файл
5. Появится сообщение «Импортировано: NNN товаров»

Готово.

---

## Если `sqlite3` не установлен на VDS

После шага 1 (когда вы на VDS) выполните один раз:

```
apt install -y sqlite3
```

Потом возвращайтесь к шагу 2.

## Структура `catalog.xlsx` (что читает импорт)

| Колонка в xlsx | Куда попадает |
|---|---|
| `Артикул` | `article` (уникальный) — обязательно |
| `Название` | `name` — обязательно |
| `Описание` | `description` — опционально |
| `Цвета` | `colors` — опционально |
| `Фото (URL)` | `photo_url` — опционально |

Строки без `Артикул` пропускаются. Один артикул — одна позиция (повторы заменяют друг друга).

## Если что-то пошло не так

- **«database is locked»** при выполнении DELETE — кратковременно: подождите 1 секунду и повторите. Если упорно — `systemctl restart uv-calc.service` и снова DELETE.
- **«no such table: catalog_items»** — что-то с миграциями. Запустите на VDS:
  ```
  sudo -u uvcalc -E node /opt/uv-calc/migrate.js
  ```
- **Хочется откатиться к состоянию до неправильного импорта** — взять последний бэкап БД:
  ```
  systemctl stop uv-calc.service
  cp /opt/uv-calc/data/backups/uv-YYYY-MM-DD.db /opt/uv-calc/data/uv.db
  chown uvcalc:uvcalc /opt/uv-calc/data/uv.db
  systemctl start uv-calc.service
  ```
  (где `YYYY-MM-DD` — нужная дата, `ls /opt/uv-calc/data/backups/` покажет список).
