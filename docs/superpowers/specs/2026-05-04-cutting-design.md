# Высечка на плоттере и лазере

## Что добавляем

В калькулятор УФ-печати добавляется третий тип расчёта — **высечка**, с двумя подтипами:

- `cutting_plotter` — контурная резка на режущем плоттере (плёнки, тонкие листовые материалы)
- `cutting_laser` — резка на CO₂-лазере (картон, акрил, фанера, фетр и т.п.)

Сейчас в калькуляторе работают два типа: `sheet` (листовая УФ-печать) и `souvenir` (УФ-печать на сувенирке). Высечка — параллельный третий блок, не пересекается с печатью по логике, ставкам и UI. Реализуется как новая функция `calcCutting()` в `calc.js` рядом с `calcSheet()` и `calcSouvenir()`.

## Модель тарификации

**По погонным метрам реза.** Менеджер вводит длину контура реза в метрах (берёт цифру из макета — Illustrator/CorelDraw показывают суммарную длину выделенных контуров).

Решение принято на основе анализа рынка (см. «Источники» в конце документа). Альтернативы — по штукам, по м², по времени работы станка — отклонены: погонные метры дают точный расчёт независимо от формата изделия и сложности раскладки на листе.

## Прайс

### Плоттер (одна ставка на материал)

Толщина для плоттера не критична — нож-капля одинаково режет тонкие плёнки и тонкие листовые материалы. Различие в стоимости — по типу материала.

| Материал | ₽/м.п. |
|---|---|
| Oracal (самоклейка-винил) | 30 |
| Самоклейка-бумага | 35 |
| ПВХ-плёнка | 40 |
| Магнитный винил | 60 |
| Гофрокартон | 25 |
| Каппа (пенокартон) | 50 |
| ПВХ вспененный | 80 |

### Лазер (материал × толщина)

Толщина критична — лазер режет 10 мм акрила в 7-10 раз медленнее, чем 1 мм. Без учёта толщины прайс был бы либо завышен на тонкое (потеря заказов), либо убыточен на толстое.

| Материал | Толщина | ₽/м.п. |
|---|---|---|
| Картон/бумага | 1 мм | 20 |
| Гофрокартон | 3 мм | 30 |
| Гофрокартон | 5 мм | 45 |
| Фетр/кожа | — (одна позиция) | 40 |
| Каппа | 3 мм | 30 |
| Каппа | 5 мм | 50 |
| Акрил | 1 мм | 25 |
| Акрил | 3 мм | 50 |
| Акрил | 5 мм | 90 |
| Акрил | 10 мм | 165 |
| Фанера/МДФ | 3 мм | 40 |
| Фанера/МДФ | 5 мм | 70 |
| Фанера/МДФ | 10 мм | 140 |

ПВХ на лазере не режется (выделение хлора при нагреве — портит станок и вредно для оператора). В прайсе лазера ПВХ отсутствует.

Все ставки — стартовый ориентир по рынку РФ (медиана Москва+СПб). Анна корректирует через админку после первого деплоя.

## Формула

```
base    = price_per_m × длина_реза_м
если ☐ Сложный контур:  base = base × 1.20
если ☐ Срочный заказ:   base = base × 1.30
total   = max(base, cutting_min_order)
```

Множители применяются последовательно (мультипликативно): срочный + сложный = ×1.20 × 1.30 = ×1.56. Это совместимо с текущей логикой `calcSheet`/`calcSouvenir`, где `urgent` уже работает как `× 1.30`.

Минимум применяется в самом конце — после всех надбавок. Стартовое значение — **1500 ₽**, общее для плоттера и лазера, редактируется через админку.

### Пример

Каппа 5 мм, длина реза 12.5 м, срочный + сложный контур:
```
50 × 12.5      = 625 ₽
× 1.20         = 750 ₽
× 1.30         = 975 ₽
max(975, 1500) = 1500 ₽   ← применён минимум
```

Если бы длина была 30 м:
```
50 × 30        = 1500 ₽
× 1.20         = 1800 ₽
× 1.30         = 2340 ₽
max(2340, 1500) = 2340 ₽  ← минимум не применился
```

## База данных

### Миграция v6

Новая таблица `cutting_materials`:

```sql
CREATE TABLE cutting_materials (
  id            INTEGER PRIMARY KEY AUTOINCREMENT,
  service       TEXT    NOT NULL CHECK (service IN ('plotter', 'laser')),
  name          TEXT    NOT NULL,
  thickness_mm  REAL,                        -- NULL для плоттера, число для лазера
  price_per_m   REAL    NOT NULL,
  sort_order    INTEGER NOT NULL DEFAULT 0,
  is_active     INTEGER NOT NULL DEFAULT 1,
  created_at    TEXT    NOT NULL DEFAULT (datetime('now')),
  updated_at    TEXT    NOT NULL DEFAULT (datetime('now'))
);

CREATE INDEX idx_cutting_materials_service ON cutting_materials(service, is_active, sort_order);
```

В `company_settings` добавляется ключ `cutting_min_order` со значением `1500`.

Стартовый прайс из таблиц выше засеивается в миграции (idempotent — через `INSERT OR IGNORE` по уникальному ключу `(service, name, thickness_mm)`; для строгости добавляется уникальный индекс):

```sql
CREATE UNIQUE INDEX uniq_cutting_materials
  ON cutting_materials(service, name, COALESCE(thickness_mm, -1));
```

`COALESCE(thickness_mm, -1)` нужен потому, что SQLite трактует NULL как «не равно ничему» в UNIQUE — без этого две записи плоттера с одинаковым `name` не будут конфликтовать.

## Расчёт (`calc.js`)

```js
function calcCutting({ materialId, lengthM, urgent, complexContour }, materials, settings) {
  const material = materials.find(m => m.id === materialId)
  if (!material) throw new Error('Material not found')
  if (!Number.isFinite(lengthM) || lengthM <= 0) throw new Error('Invalid length')

  let base = material.price_per_m * lengthM
  if (complexContour) base *= 1.20
  if (urgent)         base *= 1.30

  const minOrder = Number(settings.cutting_min_order) || 1500
  const minOrderApplied = base < minOrder
  const total = minOrderApplied ? minOrder : base

  return {
    service:           material.service,
    materialName:      material.name,
    thicknessMm:       material.thickness_mm,
    pricePerM:         material.price_per_m,
    lengthM:           +lengthM,
    complexContour:    !!complexContour,
    urgent:            !!urgent,
    base:              +base.toFixed(2),
    minOrder:          minOrder,
    minOrderApplied:   minOrderApplied,
    total:             +total.toFixed(2),
  }
}

module.exports = { calcSheet, calcSouvenir, calcCutting }
```

## API

| Метод | Путь | Доступ | Поведение |
|---|---|---|---|
| GET | `/api/cutting-materials?service=plotter\|laser` | auth | Список **только активных** материалов, отсортированный по `sort_order, id`. Используется в калькуляторе. |
| GET | `/api/cutting-materials/all?service=plotter\|laser` | admin | Все материалы (включая `is_active=0`). Используется в админке. |
| POST | `/api/cutting-materials` | admin | Создать. Body: `{service, name, thickness_mm, price_per_m, sort_order?}`. |
| PUT | `/api/cutting-materials/:id` | admin | Частичное обновление. Body может содержать любое подмножество полей. |
| DELETE | `/api/cutting-materials/:id` | admin | Soft-delete: устанавливает `is_active=0`. |

Параметр `service` обязателен в обоих GET (без него возвращается 400). Это защита от случая, когда UI забыл фильтр и в селекте плоттера появился акрил.

`PUT /api/company-settings` уже принимает произвольные ключи (фаза F) — `cutting_min_order` интегрируется без изменений в API. UI добавляет одно поле ввода.

## UI калькулятора

В `public/index.html` сейчас два режима — «Листовая печать / Сувенирка». Добавляется третий — «Высечка». Переключатель режима остаётся прежним по логике; добавляется одна кнопка/таб.

Поля блока «Высечка»:

| Поле | Тип | Поведение |
|---|---|---|
| Услуга | radio: Плоттер / Лазер | Переключает фильтр материалов в селекте |
| Материал | `<select>` | Загружается через `GET /api/cutting-materials?service=...` при смене радио. Для лазера отображается как «Акрил 5 мм», для плоттера — «Oracal». |
| Длина реза, м | `<input type="number" step="0.1" min="0">` | Подсказка под полем: «Длину контура смотрите в макете (Illustrator / CorelDraw показывают суммарную длину)». |
| Срочный заказ (+30%) | checkbox | |
| Сложный контур (+20%) | checkbox | |
| Кнопка «Рассчитать» | | |

Результат отрисовывается в существующем блоке вывода (тот же `#calc-result`), формат:

```
Каппа 5 мм · 12.5 м.п. × 50 ₽/м.п. = 625 ₽
+ сложный контур × 1.20            = 750 ₽
+ срочный × 1.30                   = 975 ₽
─────────────────────────────────
Базовый расчёт                     975 ₽
Применён минимум заказа         → 1500 ₽
ИТОГО                            1500 ₽
```

Если минимум не применился — последняя строка просто `ИТОГО 2340 ₽` без пометки про минимум.

## Сохранение в КП

`quotes.quote_type` — текстовое поле, миграция БД не требуется. Добавляются два новых значения: `cutting_plotter`, `cutting_laser`. Поиск/фильтрация в админке (фаза E) уже умеет фильтровать по `quote_type`.

`quotes.result` (JSON) для высечки — формат, возвращаемый `calcCutting()` (см. выше). Все поля читаемые человеком, без кодов.

`quotes.total` (фаза E) — записывается финальная сумма, фильтры/сортировки в админке заработают сразу без правок.

## План реализации

Шесть последовательных задач. Подход — Subagent-Driven (как в фазах A-H).

1. **Миграция v6** — новая таблица + индекс + сидирование прайса + `cutting_min_order` в settings. Тесты в `migrate.test.js`.
2. **`calc.calcCutting()`** — TDD: тесты → реализация. Экспорт из `calc.js`.
3. **API `/api/cutting-materials`** — пять endpoints с auth/admin guards. Файл `tests/cutting.api.test.js` (новый).
4. **UI калькулятора** — третий режим «Высечка» в `public/index.html` + `public/js/calc-ui.js`. Селект материалов с фильтром по услуге. Рендер результата с разбивкой и пометкой «применён минимум».
5. **UI админки** — вкладка «✂️ Высечка» в `public/admin.html` + `public/js/admin.js`. Секции «Плоттер» и «Лазер». Поле «Минимум заказа высечки» в настройках компании.
6. **Интеграция в save flow + PDF** — `quote_type=cutting_*` в save flow калькулятора, ветка в `kp_text`, локализация ключей в `pdf.js`, тесты PDF.

После выполнения всех 6 задач — Анна проводит smoke-тест на проде: создать тестовый КП на плоттер и на лазер, сохранить, скачать PDF, удостовериться что фильтры в «Сохранённых КП» отрабатывают.

## Открытые вопросы (на потом, не блокеры)

1. **Скидка от объёма (>500 м.п. → -15%)** — в индустрии используется, но у Сити Принт типичные тиражи маленькие. Не включена в стартовую модель. Если за 1-2 месяца появится много заказов >100 м.п. — добавим как ступенчатый прайс (как в сувенирке).
2. **Гравировка на лазере** — отдельная услуга, считается по см² (рынок: ~2 ₽/см²). Не включена в текущий дизайн. Если Анна решит её запускать — отдельный мини-спек, добавится как ещё одно `service` в `cutting_materials` или отдельная таблица.
3. **Мульти-материал в одном заказе** — сейчас одна позиция = один материал. Если клиент хочет резку и плоттером, и лазером в одном КП — менеджер делает два отдельных расчёта и объединяет вручную. Добавление мульти-позиций потребует переработки UI и save flow — отложено.
